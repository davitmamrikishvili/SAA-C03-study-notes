# 📦 AWS Storage Gateway

> [!INFO] Definition
> **AWS Storage Gateway** is a virtual or physical storage appliance that runs on-premises (or in an AWS VPC) and elegantly bridges your on-premises network with AWS cloud storage.

It handles data transfer, local caching, and provides standard on-premises storage protocols (NFS, SMB, iSCSI) so your existing applications don't need to be rewritten to interface with AWS storage APIs.

---

## 🏗️ Deployment Scenarios
* **Cloud Storage Extension**: Using AWS as a virtually infinite storage extension for on-premises hosts.
* **Cloud Backups & DR**: Replicating local volume storage asynchronously into AWS for backup/Disaster Recovery (DR).
* **Tape Migration**: Seamlessly migrating physical tape backup workflows to cloud storage.

---

## 🗂️ The Three Gateway Modes

Storage Gateway operates in three distinct modes, determining how it presents storage to your local network (File, Tape, or Block).

### 1. File Gateway
Provides seamless access to Amazon S3 for on-premises applications using standard file protocols.
* **Protocols**: SMB and NFS.
* **How it works**: Files written to the gateway are mapped and uploaded as standard **S3 objects**. Directories become S3 prefixes.
* **Integration**: Can natively integrate with Active Directory (AD) to control file share access.
* **Lifecycle**: Since the data lands as normal S3 objects, you can leverage standard S3 Lifecycle Policies to transition older data to cheaper classes (like S3 Glacier) based on access patterns.

![[StorageGateway-FILE.png]]

### 2. Tape Gateway (VTL - Virtual Tape Library)
A drop-in replacement for physical robotic tape backup libraries.
* **Protocol**: iSCSI (presented to backup software as a tape drive/library).
* **How it works**: The gateway pretends to be physical tape infrastructure. You continue to use your existing backup software (e.g., Veeam, NetBackup) identically, but without physical tapes.
* **Storage backend**: "Active" virtual tapes are stored in standard **S3** for fast retrieval. When a tape is ejected and "archived", the gateway automatically shifts that data into **S3 Glacier**.
* **Limits**: Virtual tapes range from 100 GiB – 5 TiB. An active threshold of 1 PB (across 1500 tapes), with unlimited archive scaling.

![[StorageGateway-TAPE.png]]

### 3. Volume Gateway (Block-level Storage)
Presents cloud-backed block storage volumes to your on-premises servers. Imagine AWS EBS volumes, but attached to on-premises physical servers.
* **Protocol**: iSCSI.
* **AWS Integration**: All backups generated by a Volume Gateway are stored as **EBS Snapshots** inside AWS, making them bootable into EC2 instances during a DR scenario.

Volume Gateway has two very distinct sub-modes:

**Stored Volumes**
* **Primary data is stored LOCALLY!** The gateway maintains the entire dataset on local attached disks.
* **AWS Role**: Asynchronously replicates the data to AWS for offsite backup.
* **Benefit**: Total local-speed performance, perfect for DR or business continuity.
* **Limits**: 32 volumes max; 16 TB per volume (512 TB total capacity).

![[StorageGateway-VOLUME-1.png]]

**Cached Volumes**
* **Primary data is stored IN AWS!** The gateway leverages AWS (S3-backed) as the primary storage.
* **AWS Role**: Infinite storage bucket. The local gateway acts only as a **cache** holding recently/frequently accessed blocks for lower latency.
* **Benefit**: Ideal for when your data center is out of physical disk space, but you need to expand volume capacity without buying more SAN arrays.
* **Limits**: 32 volumes max; 32 TB per volume (1 PB total capacity).

![[StorageGateway-VOLUME-2.png]]
